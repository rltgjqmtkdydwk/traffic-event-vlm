# traffic-event-vlm

횡단보도 영상에서 교통 이벤트(무단횡단, 킥보드 위반 등)를 찾고, 영상에 대해 질문하면 답해주는 걸 목표로 하는 개인 프로젝트입니다.

(아직 진행 중이라 결과 부분은 비어 있습니다. 하나씩 채워나갈 예정.)

## 개요

VLM(Vision-Language Model)한테 프레임을 보여주면 "킥보드를 탄 채로 횡단보도를 건너고 있음" 같은 판단까지 해준다. 근데 CCTV 영상을 전부 VLM에 넣는 건 너무 느리고 비싸다. 대충 계산해보면 카메라 1대, 1fps, 하루 24시간이면 이미지가 8만 장 넘게 나온다.

YOLO는 빠른데 "차도에 사람 있음"까지만 알고, 그게 위반인지는 모른다.

그래서 궁금했던 건:

- YOLO로 수상한 구간만 골라서 VLM에 넘기면 호출을 얼마나 줄일 수 있나?
- 그때 정확도는 얼마나 떨어지나?
- 모델을 양자화해서 로컬에서 돌리면 어디까지 버티나?

## 파이프라인

```
영상 → 프레임 샘플링 → YOLO + 트래킹 → ROI 트리거 규칙 ─(후보 구간)→ VLM 판정 → 이벤트 로그 → 리포트 / QA
                                              └─(해당 없음)→ skip
```

비교는 세 단계로 한다.

1. 기준선: 모든 프레임을 VLM(Gemini)에 넣음
2. 캐스케이드: YOLO 트리거 걸린 구간만 VLM 호출
3. 경량화: YOLO ONNX 변환 + INT8, VLM은 로컬 소형 모델 + 4bit

## 이벤트

YOLO 규칙만으로는 판단이 안 되는 걸 위주로 골랐다. 자세한 기준은 [docs/event_spec.md](docs/event_spec.md).

- `jaywalk` 무단횡단
- `pm_violation` 킥보드 위반 (헬멧 미착용 / 2인 탑승 / 탄 채로 횡단보도 통과)
- `right_turn_no_stop` 우회전 일시정지 위반 — 판단이 제일 애매해서 상황 보고 뺄 수도 있음

장시간 정차 같은 건 YOLO + 트래킹으로 거의 다 잡혀서 VLM 쓸 이유가 없어 제외했다.

## 데이터

공개 데이터셋 중에 한국 횡단보도 + 위 이벤트를 다룬 게 마땅치 않아서 직접 찍었다.

- 횡단보도가 내려다보이는 고정 시점에서 촬영
- 10~30초 클립으로 잘라서 이벤트 시작/끝 시간을 직접 라벨링
- 목표: 이벤트별 8~10개 + 이벤트 없는 클립 10개 정도

개인정보 관련해서는

- 원본 영상은 로컬에만 두고 레포에 안 올림
- 레포에 올리는 이미지/GIF는 얼굴, 번호판 블러 처리(개인신원특정 방지)
- 오디오는 제거(통신비밀보호법 위반 방지)

## 실행

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

`.env`에 Gemini API 키 넣기

```
GEMINI_API_KEY=...
```

실행 방법은 파이프라인 만들면서 추가 예정.

## 폴더 구조

```
src/        파이프라인 코드
```
